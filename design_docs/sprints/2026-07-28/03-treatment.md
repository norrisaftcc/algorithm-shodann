# Commit B — treatment

Written after reading `norrisaftcc/the_algorithm`. Commit A was pushed at
`2026-07-28T17:05:29-04:00`; the clone was created at `17:07:37`. Right order,
2m08s apart, both timestamps external. The barrier held and is checkable.

---

## The hypothesis was unfalsifiable

Commit A predicted: *"the treatment will not change the top three."*

**There is no treatment that produces a ranking.** `the_algorithm` has two
operations and neither prioritizes anything:

- **PROVIDE** — compress a draft prompt to the shortest version that clears a
  floor test, teach through the cuts, freeze at a gate, execute exactly.
- **ASSAY** — run the floor test against a received document, report what
  survives, read-only, never redrafted.

It is a discipline for **getting to a frozen contract**, not for ordering a
backlog. The whole A-versus-B comparison was built on the assumption that a
repository described as holding "proposed workflows... involving requirements and
prioritization" would contain a prioritization method. It contains a gate.

**Result: null, and not the interesting kind.** The prediction could not be wrong
because the experiment could not run. That is a design error in the experiment,
not a finding about the method.

## What the treatment does apply to

The documents I wrote. ASSAY takes any received document and reports what is
load-bearing. Commit A is a received document.

So the honest application of the treatment is to run it on the pre-registration
itself. Below, in the fixed template.

## Three findings the treatment produced anyway

### 1. `ste100` was an instruction, and I missed it

> "hypothetically ultracode plan document, in ste100"

**ASD-STE100** is Simplified Technical English. `SKILL.md` → Language lock:
*all output conforms to ASD-STE100. One word per meaning. At most 20 words per
instruction. Active voice. Imperative mood. No idioms.*

I read it as an unparseable token, guessed it meant "pitch it for an outside
reader," said so, and wrote 900 words of prose. The instruction was specific,
checkable, and vendored in the repository I was about to be handed.

Every sprint document in this directory violates the lock.

### 2. The method was governing the session the whole time

The gate is `the_algorithm`. Reading `Gate integrity` against the transcript:

| Doctrine | What happened |
|---|---|
| "Only a human opens the gate." | "gate is: you and i are aligned in intent" |
| "The Algorithm asks the gate question; it never answers it." | "will give you a go / no go on gate after" |
| "No completion assist. Ambiguous assent does not open the gate." | "no go but close" — four times |
| "Negotiation side: the contract may only be revised." | "we're still negotiating in front of the execution gate" |
| Seats: name the seat before speaking from it | "pretend you're the product owner i'm the onsite customer" |

Not an influence. The protocol, run live, with me inside it.

### 3. The control protected the wrong variable

I built a timestamped barrier so my ranking would not be contaminated by their
method — and their method was already running the conversation that produced the
ranking. Contamination was total before the sprint began, in a direction the
contamination register does not have a row for.

The register logged a repo name seen in a `gh repo list` as trivial. It did not
log that every gate, every "no go but close", and the seat assignment came from
the document I was protecting the experiment from.

**A spawned agent cannot know what it was not told.** Neither can this one.

## Does this change the ranking?

No — and now for a reason worth recording rather than a null.

ASSAY does not reorder items. It found that the ranking's **operative content is
buried**, not that the order is wrong. The four items and their sequence survive
compression intact; 97% of the document does not.

So the treatment's verdict on commit A is: *the decisions are sound, the document
carrying them is below floor.* That is a real finding, and it is not the finding
the experiment was built to detect.

## Cost

Commit A: ~1400 words. Its residue: 45. The compression the method asks for is
**31:1** on my own prioritization document.
